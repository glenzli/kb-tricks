# Agent Instructions

Before planning or editing this repository:

1. Read `DEV_SKELETON.md`.
2. Read `REVIEW_SKELETON.md` when reviewing or changing code.
3. Treat skeleton files as orientation, not authority.
4. Verify factual claims against source code, tests, config, release artifacts, or maintained docs.
5. Before extending a growing module, classify the change as a cohesive extension, a new responsibility, or an exposed boundary.

Do not create long-lived implementation summaries without explicit justification.
Keep code with one semantic owner together, and separate responsibilities that change independently. Do not split by file size alone.
